# 店舗メニュー案内ページ

## 1. 目的とコンセプト

席のQRコードから開く、来店回数の確認と任意アンケートを備えたメニュー案内ページです。初回のお客様には来店経路を尋ね、回答後は店舗のメニューへ案内します。一度アンケート画面からメニューへ進んだブラウザーでは回答済み状態を保存し、次回のアクセスではアンケートを表示せずメニューへ直接遷移します。たとえ席移動したとしても、回答済み状態がお客の端末（ブラウザ）内に保存されるので、QRコードを読んだのが同じ端末・同じブラウザなら、メニューへ直接遷移できます。

ページ本体は静的なHTMLです。席トークンとAirレジURLの対応管理にはGoogle Apps Script（GAS）のウェブアプリを使用します。

## 2. 基本の画面遷移

1. **席トークンの確認とURL取得**：QRコードのURLに含まれる `token` を読み取り、GASウェブアプリへ問い合わせます。GASからそのトークンに対応するAirレジURLを取得できない場合、エラーを表示して遷移しません。有効な場合は、日本時間の日付を含むキーでブラウザーの `localStorage` を確認します。当日回答済みならアンケートを表示せず、その席のメニューへ移動します。
2. **来店回数の選択**：「初めてのご来店」では流入元アンケートへ、「2回目以降のご来店」では当日回答済み状態と来店回数を保存・送信し、案内画面の後にメニューへ移動します。
3. **アンケート回答**：流入元を任意で選び、「メニューを見る」を押すと当日回答済み状態を保存し、回答を送信してメニューへ移動します。

## 3. ファイルと画面構造

- `index.html`：画面、スタイル、画面遷移、GASからの席別URL取得、Googleフォーム送信、回答状態の確認・保存をまとめたメインファイルです。
- `images`フォルダ内の`top.png`：初期画面に表示するバナー画像です。広告画像を貼ることができます。この名称以外の画像は実際のページには使われません。

画面は、来店回数を尋ねる初期画面、リピーター向けウェルカム画面、初回向けアンケート画面の3つのステップで構成されています。CSSで初期表示を制御し、JavaScriptでステップを切り替えます。

## 4. 詳細な動作とデータ

- **席ごとのメニュー遷移先**：AirレジURLと席トークンの対応はGAS側で管理し、HTML内には席別URLの対応表を置きません。GASウェブアプリは `index.html` からの `GET` リクエストを受け、クエリの `token` に対応するURLをJSON（`{"airregiUrl":"https://spo.order.airregi.jp/..."}`）で返す必要があります。未登録・無効なトークンにはURLを返さないようにしてください。ページ側でも、返されたURLがHTTPSの `spo.order.airregi.jp` ホストであることを検証します。
- **各席のアクセス用URL**：QRコードは公開ページに推測困難なランダムトークンを付けて作成します。例：`https://ska0151.github.io/shop-menu-gate/?token=ランダムなトークン`。従来の `?seat=8` 形式は使用しません。トークンは連番や席番号などから推測できる値にせず、席ごとに別の値を発行し、GAS側の対応表に登録してください。
- **GAS APIの設定とCORS**：GASウェブアプリURLは `index.html` 内の `GAS_API_URL` で設定します。ウェブアプリは公開ページから呼び出せるようデプロイし、ブラウザーの `fetch` でレスポンスを読み取れることを確認してください。CORSまたはネットワークエラー、HTTPエラー、不正なJSON、Airレジ以外のURLが返された場合は、コンソールにエラーを出し、既存の設定エラー画面を表示します。GASのデプロイ設定やレスポンス形式を変更した場合は、実際のブラウザーから動作確認してください。
- **フォーム送信先**：`GOOGLE_FORM_URL` と各 `ENTRY_...` 定数でGoogleフォームと項目IDを設定しています。送信は `fetch` の `no-cors` モードで非同期に行います。つまりGoogle formへのデータ送信完了を待たずにメニュー画面に遷移するので、お客を待たせることなくメニュー表示します。
- **公開情報に関する注意**：GAS API URLはクライアントコードに含まれるため公開されます。トークンもQRコードとページURLに含まれ、利用者から見えます。GAS側ではトークンの値だけでアクセスを許可するため、漏えいしたトークンは第三者に使われる可能性があります。トークンを秘密の認証情報として扱い、公開の場に掲載しないでください。またGoogleフォームはブラウザーから直接送信するため、その送信先URLとフォーム項目IDもページソースから確認できます。
- **回答済み状態**：`shopMenuGateSurveyCompleted:YYYY-MM-DD` 形式のキーに `"true"` を `localStorage` へ保存します。日付は日本時間で判定し、日付が変わると新たな回答が必要になります。初回アンケートの送信操作と「2回目以降」の選択を当日回答済みとして記録します。Googleフォーム側の回答や本人を照合するものではありません。
- **席ごとのQRコードと回答状態**：同じ端末・同じブラウザーで、各QRコードが同じオリジン（プロトコル・ホスト名・ポート）のページを開く場合、トークンのクエリが異なっていても回答状態を共有します。オリジンが異なる場合は共有されません。当日回答済みの場合も、現在のQRコードのトークンに対応するAirレジURLへ遷移します。
- **保存・確認に失敗した場合**：エラーをコンソールに出力します。保存失敗時も今回のメニュー遷移は続きますが、当日回答済みとして記録できないため、次回はアンケート画面が表示されます。確認失敗時は回答済みとみなさず、アンケート画面を表示します。
- **状態の範囲**：回答済み状態は同じブラウザー・同じオリジンの保存領域に保持されます。別のブラウザーや端末とは共有されず、保存データの消去やプライベートブラウズでは状態が引き継がれない場合があります。日付ごとのキーを使うため、過去日のキーは `localStorage` 内に残りますが、当日の判定には使われません。

## 5. 更新・動作確認

画面文言やスタイルは `index.html` 内のHTML/CSSを編集します。席別メニューURLとトークンの対応はGAS側で管理してください。席ごとに推測困難なトークンを発行し、対応するAirレジURLとともにGASへ登録したうえで、公開先URLに `?token=トークン` を付けたQRコードを作成します。GASウェブアプリURLを変更する場合は、同ファイル内の `GAS_API_URL` を更新してください。GoogleフォームURLとフォーム項目IDを変更する場合は、同ファイル内の設定定数を更新してください。バナーを差し替える際は画像ファイルとHTML内の参照先を合わせます。

公開先ページを、GASに登録した有効なトークン付きURLで開いて確認します。動作確認では、有効なトークンで対応するAirレジURLが取得されること、トークン未指定・未登録の場合やGASへの通信失敗時にエラー案内が表示されて遷移しないことを確認してください。また、GASがAirレジ以外のホストを返した場合も遷移しないことを確認します。あわせて初回表示、リピーター選択後の当日スキップ、アンケート送信後の当日スキップ、および日本時間の日付変更後に再度アンケートが表示されることを確認します。
