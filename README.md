# 店舗メニュー案内ページ

## 1. 目的とコンセプト

席のQRコードから開く、来店回数の確認と任意アンケートを備えたメニュー案内ページです。初回のお客様には来店経路を尋ね、回答後は店舗のメニューへ案内します。一度アンケート画面からメニューへ進んだブラウザーでは回答済み状態を保存し、次回のアクセスではアンケートを表示せずメニューへ直接遷移します。

ページは静的なHTMLで構成され、ビルドやサーバー側のアプリケーションを必要としません。

## 2. 基本の画面遷移

1. **回答状態の確認**：ページ読み込み時に日本時間の日付を含むキーでブラウザーの `localStorage` を確認します。当日回答済みならアンケートを表示せずメニューへ移動します。
2. **来店回数の選択**：「初めてのご来店」では流入元アンケートへ、「2回目以降のご来店」では当日回答済み状態と来店回数を保存・送信し、案内画面の後にメニューへ移動します。
3. **アンケート回答**：流入元を任意で選び、「メニューを見る」を押すと当日回答済み状態を保存し、回答を送信してメニューへ移動します。

## 3. ファイルと画面構造

- `index.html`：画面、スタイル、画面遷移、フォーム送信、回答状態の確認・保存をまとめたメインファイルです。
- `images/top.png`：初期画面に表示するバナー画像です。
- `images/2026_osechi_reservation.png`：リポジトリに含まれる画像素材です。現在の `index.html` からは参照されていません。

画面は、来店回数を尋ねる初期画面、リピーター向け案内画面、初回向けアンケート画面の3つのステップで構成されています。CSSで初期表示を制御し、JavaScriptでステップを切り替えます。

## 4. 詳細な動作とデータ

- **メニュー遷移先**：`AIRREGI_URL` に設定したURLです。席ごとに異なるURLを使う場合は、各席のページ設定に合わせてください。
- **フォーム送信先**：`GOOGLE_FORM_URL` と各 `ENTRY_...` 定数でGoogleフォームと項目IDを設定しています。送信は `fetch` の `no-cors` モードで非同期に行います。
- **回答済み状態**：`shopMenuGateSurveyCompleted:YYYY-MM-DD` 形式のキーに `"true"` を `localStorage` へ保存します。日付は日本時間で判定し、日付が変わると新たな回答が必要になります。初回アンケートの送信操作と「2回目以降」の選択を当日回答済みとして記録します。Googleフォーム側の回答や本人を照合するものではありません。
- **席ごとのQRコード**：同じ端末・同じブラウザーで、各QRコードが同じオリジン（プロトコル・ホスト名・ポート）のページを開く場合、パスやクエリが異なっていても回答状態を共有します。オリジンが異なる場合は共有されません。
- **保存・確認に失敗した場合**：エラーをコンソールに出力します。保存失敗時も今回のメニュー遷移は続きますが、当日回答済みとして記録できないため、次回はアンケート画面が表示されます。確認失敗時は回答済みとみなさず、アンケート画面を表示します。
- **状態の範囲**：回答済み状態は同じブラウザー・同じオリジンの保存領域に保持されます。別のブラウザーや端末とは共有されず、保存データの消去やプライベートブラウズでは状態が引き継がれない場合があります。日付ごとのキーを使うため、過去日のキーは `localStorage` 内に残りますが、当日の判定には使われません。

## 5. 更新・動作確認

画面文言やスタイルは `index.html` 内のHTML/CSSを編集します。メニューURL、フォームURL、フォーム項目IDを変更する場合は、同ファイル内の設定定数を更新してください。バナーを差し替える際は画像ファイルとHTML内の参照先を合わせます。

静的ページのため、`index.html` をブラウザーで開いて確認できます。運用環境では、各席のQRコードがこのページを指すように設定してください。初回表示、リピーター選択後の当日スキップ、アンケート送信後の当日スキップ、および日本時間の日付変更後に再度アンケートが表示されることを確認します。
