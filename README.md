# 店舗メニュー案内ページ

## 1. 目的とコンセプト

席のQRコードから開く、来店回数の確認と任意アンケートを備えたメニュー案内ページです。初回のお客様には来店経路を尋ね、回答後は店舗のメニューへ案内します。一度アンケート画面からメニューへ進んだブラウザーでは回答済み状態を保存し、次回のアクセスではアンケートを表示せずメニューへ直接遷移します。たとえ席移動したとしても、回答済み状態がお客の端末（ブラウザ）内に保存されるので、QRコードを読んだのが同じ端末・同じブラウザなら、メニューへ直接遷移できます。

ページは静的なHTMLで構成され、ビルドやサーバー側のアプリケーションを必要としません。

## 2. 基本の画面遷移

1. **席番号と回答状態の確認**：QRコードのURLに含まれる `seat` パラメーターから席番号を読み取り、席番号に対応するAirレジURLを選びます。有効なURLが設定されていない場合はエラーを表示し、遷移しません。有効な場合は、日本時間の日付を含むキーでブラウザーの `localStorage` を確認します。当日回答済みならアンケートを表示せず、その席のメニューへ移動します。
2. **来店回数の選択**：「初めてのご来店」では流入元アンケートへ、「2回目以降のご来店」では当日回答済み状態と来店回数を保存・送信し、案内画面の後にメニューへ移動します。
3. **アンケート回答**：流入元を任意で選び、「メニューを見る」を押すと当日回答済み状態を保存し、回答を送信してメニューへ移動します。

## 3. ファイルと画面構造

- `index.html`：画面、スタイル、画面遷移、フォーム送信、回答状態の確認・保存をまとめたメインファイルです。
- `images`フォルダ内の`top.png`：初期画面に表示するバナー画像です。広告画像を貼ることができます。この名称以外の画像は実際のページには使われません。

画面は、来店回数を尋ねる初期画面、リピーター向けウェルカム画面、初回向けアンケート画面の3つのステップで構成されています。CSSで初期表示を制御し、JavaScriptでステップを切り替えます。

## 4. 詳細な動作とデータ

- **席ごとのメニュー遷移先**：`AIRREGI_URLS` に席番号とAirレジURLの組み合わせを設定します。各AirレジURLは席ごとに異なるため、Airレジで発行した席別QRコードから実際のURLを取得して設定してください。現在は8番席のみ実URLを設定し、1〜7番席と9〜10番席は `example.invalid` ドメインのダミーURLです。ダミーのままでは安全のため遷移せず、席情報エラーが表示されます。席の数に合わせて設定を追加・削除し、ダミーを実URLに置き換えてください。
- **各席のアクセス用URL**：各QRコードは、同じ `index.html` に席番号を付けて開きます。例として、公開先のページURLが `https://example.com/shop-menu-gate/index.html` の場合、8番席は `https://example.com/shop-menu-gate/index.html?seat=8`、9番席は `https://example.com/shop-menu-gate/index.html?seat=9` です。`example.com` とパスは実際の公開先に置き換えてください。席番号が未指定、未登録、または対応する値がAirレジのURLではない場合は、アンケートを表示せずエラー案内を表示します。
- **フォーム送信先**：`GOOGLE_FORM_URL` と各 `ENTRY_...` 定数でGoogleフォームと項目IDを設定しています。送信は `fetch` の `no-cors` モードで非同期に行います。つまりGoogle formへのデータ送信完了を待たずにメニュー画面に遷移するので、お客を待たせることなくメニュー表示します。
- **回答済み状態**：`shopMenuGateSurveyCompleted:YYYY-MM-DD` 形式のキーに `"true"` を `localStorage` へ保存します。日付は日本時間で判定し、日付が変わると新たな回答が必要になります。初回アンケートの送信操作と「2回目以降」の選択を当日回答済みとして記録します。Googleフォーム側の回答や本人を照合するものではありません。
- **席ごとのQRコードと回答状態**：同じ端末・同じブラウザーで、各QRコードが同じオリジン（プロトコル・ホスト名・ポート）のページを開く場合、席番号のクエリが異なっていても回答状態を共有します。オリジンが異なる場合は共有されません。当日回答済みの場合も、現在アクセスしているQRコードの席番号に対応するAirレジURLへ遷移します。
- **保存・確認に失敗した場合**：エラーをコンソールに出力します。保存失敗時も今回のメニュー遷移は続きますが、当日回答済みとして記録できないため、次回はアンケート画面が表示されます。確認失敗時は回答済みとみなさず、アンケート画面を表示します。
- **状態の範囲**：回答済み状態は同じブラウザー・同じオリジンの保存領域に保持されます。別のブラウザーや端末とは共有されず、保存データの消去やプライベートブラウズでは状態が引き継がれない場合があります。日付ごとのキーを使うため、過去日のキーは `localStorage` 内に残りますが、当日の判定には使われません。

## 5. 更新・動作確認

画面文言やスタイルは `index.html` 内のHTML/CSSを編集します。席別メニューURLは、席番号をキーに持つ `AIRREGI_URLS` を更新してください。Airレジ発行QRコードから各席のURLを確認し、ダミーURLと置き換えます。QRコードは公開先の `index.html` のURLに `?seat=席番号` を追加して作成します。GoogleフォームURLとフォーム項目IDを変更する場合は、同ファイル内の設定定数を更新してください。バナーを差し替える際は画像ファイルとHTML内の参照先を合わせます。

静的ページのため、公開先に配置した `index.html?seat=席番号` をブラウザーで開いて確認できます。8番席は `index.html?seat=8` の形式です。動作確認では、8番席の遷移、ダミーURLの席でエラー案内が出てAirレジへ遷移しないこと、席番号未指定・未登録の場合も同様に遷移しないことを確認してください。あわせて初回表示、リピーター選択後の当日スキップ、アンケート送信後の当日スキップ、および日本時間の日付変更後に再度アンケートが表示されることを確認します。
